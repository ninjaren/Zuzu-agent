📊 RAG 評估方法論

前三站把 RAG 組起來了，但「組起來」不等於「夠準」。這站講怎麼評估它的正確性和幻覺程度，而且不需要養一整個專家審核團隊才能做。

核心思路：把評估拆成「機器能自動做」和「只有人能做但量很小」

傳統做法是找領域專家一題一題看答案對不對——這在垂直領域（例如只有你一個專家撐起整個知識庫）完全撐不住。省力的做法是把評估流程拆開：大部分用自動化指標覆蓋，專家的時間只花在抽查和校準，不是逐題審核。

1. 用 LLM 當裁判自動評估

這是核心鏈路⑤「自我檢查機制」和「進階方向」②多數決驗證提過的 LLM-as-Judge 概念的延伸應用，不用自己從頭設計指標，直接套現成的開源評估框架：

工具做什麼
RAGAS（ragas.io）專門為 RAG 設計的開源評估框架，自動算出一整組標準指標
TruLens / DeepEval類似性質，偏重接進正式服務做持續監控

RAGAS 的核心指標直接對應正確性和幻覺，全部由 LLM 自動算，不需要人工比對：

  • 🎯 Faithfulness（忠實度）：生成答案裡每一句話，是不是都能在檢索回來的資料裡找到支持——直接量化幻覺程度
  • ✅ Answer Relevancy：答案有沒有真正回答到問題
  • 📏 Context Precision / Recall：檢索回來的資料精不精準、有沒有漏掉該撈到的內容（對應③講過的 Precision@k / Recall@k）

2. 測試題從「專家手寫」改成「從語料自動生成」

這是最關鍵的省力技巧，不要叫專家寫測試題：

把已有的語料（文章、FAQ、論壇精華）丟給 LLM
→ 請它針對每段內容生成「一個問題 + 這段內容就是標準答案」
→ 自動得到一組「已知正確答案在哪裡」的測試集

專家完全不用寫題目，因為正確答案本來就來自語料裡已經審過的內容。專家的工作從「出題＋改考卷」縮減成「確認原始語料本身沒錯」——而且這件事只要做一次，不是每次評估都要重做。

3. 專家的時間只花在抽查和校準裁判

  • 每週/每月抽樣 5-10% 的真實使用者問答，讓專家看一次，算出人工判斷跟 LLM 裁判的一致率
  • 一致率夠高（例如 90%+），代表 LLM 裁判可以信任，之後持續自動跑就好，專家只要偶爾抽查校準
  • 裁判本身可能有系統性偏差，但偏差是可以被偶爾校準的，不是每次都要人工覆核

4. 降低幻覺的工程手法

跟評估分開，但通常一起做：

  • 強制引用來源：要求模型標出每句話出自哪個檢索片段，沒有來源支持的句子視為高風險，程式可以自動標記
  • 檢索分數門檻：最相關的檢索結果分數太低（代表知識庫根本沒有相關資料），直接回「資料不足」，不要硬生成答案
  • 允許模型說不知道：提示詞明確鼓勵寧可說不確定也不要瞎猜，並且把「它正確說出不知道」也算進評估指標裡——這點很容易被忘記算

5. 省力建立垂直＋水平語料：把專家從作者變成審核者

做法專家角色常用技術
先彙整既有權威資料（官方公告、資料庫、技術文件、論文、論壇精華、影片轉文字）只要挑來源可信度，不用自己寫BeautifulSoup／Scrapy（網頁爬取）；影片轉文字用 Whisper（OpenAI 開源語音辨識）
LLM 輔助整理：把蒐集來的原始資料丟給 LLM 整理成結構化問答抽查一部分確認品質，不用逐篇寫任一 LLM API（Python 呼叫）＋ 輸出格式用 JSON Schema 約束結構
LLM 做知識缺口分析：分析語料庫涵蓋了哪些主題、明顯缺什麼優先補最重要的洞，不是地毯式全部補齊先用 BERTopic／簡單的 K-Means 分群既有語料找主題分佈，再讓 LLM 總結缺口
用真實使用紀錄導流：統計「檢索不到／答得差」的問題類型把有限時間花在使用者真的在問但答不好的地方日誌存 SQLite／PostgreSQL，用 pandas 做統計分析
社群協作／眾包修正：開放回報錯誤入口只需要當最後仲裁者，不用自己找錯簡單的表單（Google Forms）或網頁內建的回饋按鈕（Flask 加一個 API 端點）
關鍵心態轉換：不要想著「上線前要把知識庫做到完整」，那永遠做不完。先用現有資料上線（搭配「不確定就說不知道」機制），讓真實使用數據告訴你該優先補哪裡——這比憑經驗猜測涵蓋範圍有效率得多。

工作中真的會踩到的坑

⚠️ 只看平均分數，沒看分數的分布和趨勢

Faithfulness 平均分數 0.85 聽起來不錯，但如果這個分數是「大多數題目接近 1.0、少數幾題接近 0」平均出來的，代表系統在特定主題上系統性失敗——平均值完全藏住了這個問題。拆開看分數分布，找出低分群集中在哪個主題，比盯著單一平均數有用得多。

⚠️ LLM 裁判跟答題模型是同一顆大腦，裁判結果偏樂觀

如果用同一個模型（或同一家族模型）當裁判又當答題者，裁判很可能對自己的系統性盲點視而不見——這跟自我檢查機制那站提過的天花板是同一個問題。有條件的話，裁判用不同的模型（甚至不同供應商），能避開「自己批改自己考卷」的偏誤，這也是為什麼第 3 節的人工抽查校準步驟不能完全省略。
