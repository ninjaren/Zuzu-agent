🔗 併入對話：描述交給 qwen3 理解

llava 的文字描述最後要跟原始問題合併成一則訊息——這一步如果合併得不乾淨，前兩站的工作都白做。

對照本專案的程式碼

if image_b64:
    description = analyze_image_b64(image_b64, query or "請詳細描述這張圖片的內容")
    msgs.append({
        "role": "user",
        "content": f"[圖片分析結果]\n{description}\n\n使用者問題：{query}" if query else f"[圖片分析結果]\n{description}",
    })
else:
    msgs.append({"role": "user", "content": query})

有圖片時，送給 qwen3 的不是圖片本身，而是「[圖片分析結果] + llava 的文字描述 + 使用者問題」這樣一段純文字。

逐行拆解

  • query or "請詳細描述這張圖片的內容"：使用者只傳圖沒打字時，用預設問句問 llava，確保一定有問題傳給視覺模型
  • [圖片分析結果] 標記：清楚區分圖片描述和使用者原本想問的話，避免 qwen3 混淆
  • 三元判斷式：處理「只傳圖沒打字」的邊界情況，不加空白的「使用者問題」那段

為什麼這樣設計

qwen3 從頭到尾沒「看到」圖片，看到的永遠只是文字——呼應核心鏈路第一站：LLM 只會「輸入文字→輸出文字」。llava 的角色是幫 qwen3 把看不懂的輸入翻譯成看得懂的輸入。

完整流程圖

使用者上傳圖片 + 問題
      ↓
llava:7b 分析圖片 → 產生文字描述
      ↓
"[圖片分析結果]\n(描述文字)\n\n使用者問題：(原始問題)"
      ↓
組成一則 role=user 的訊息，塞進 msgs
      ↓
qwen3:8b 根據這整段純文字回答
（qwen3 全程「沒看過」圖片本身，只看過 llava 轉譯出來的文字）

這個設計的優點與代價

優點代價
✅ qwen3 不需要重新訓練，維持原本對話品質⚠️ 多一次 API 呼叫，回答速度變慢
✅ 兩個模型可獨立升級⚠️ 圖片細節被文字化壓縮，llava 沒提到的，qwen3 完全不知道
✅ 邏輯簡單，容易定位是哪個模型的問題⚠️ llava 描述錯了，qwen3 沒辦法回頭看一眼確認
這就是多模態橋接子地圖的全貌。這裡產出的 msgs 會接回主線地圖 ②LLM⇄Harness 橋接——一樣透過 API 把整包 messages 送進 LLM，跟記憶與 RAG 子地圖處理完的結果，最後匯流到同一個地方。

工作中真的會踩到的坑

⚠️ 使用者追問同一張圖的細節，卻查不出哪裡出錯

同一個對話裡問關於同一張圖的第二個問題，qwen3 記得的是 llava 當初的文字描述，不是圖片本身——描述已存進對話歷史，短期記憶機制會繼續帶著走。如果使用者問到描述裡沒提到的細節，qwen3 答不出來，這不是模型「忘記了」，是它從來沒有真正看過那張圖。第一次遇到使用者抱怨「它怎麼會不知道」時，容易誤以為是記憶機制壞了，實際上要回頭查的是第一次分析時 llava 的描述夠不夠完整。

⚠️ 把這個流程套用在不該用它的場景

這套「轉文字再理解」的流程，適合「描述、問答」這類語意任務，不適合需要精確像素層級判斷的場景（例如比對兩張圖是否完全相同、讀取圖片裡模糊的小字）。把它硬套到這類場景，表現會不穩定，而且錯誤型態不容易一眼看出——先確認任務性質適不適合這套架構，比事後除錯划算。

🎓 深入機制（進階，可選讀）

把兩個模型串成一條管線，會帶來誤差沿著管線累積、放大的風險。這一節講這個現象的正式名稱，以及跟幻覺概念的關聯。

1. 誤差串接（Cascading Errors）

Pipeline 架構有個系統性風險：第一階段（llava）輸出有錯，第二階段（qwen3）完全無法察覺，只能把錯誤輸入當事實繼續處理——工程上稱誤差串接或誤差傳播：每階段可能額外引入誤差，後面階段沒能力回頭檢查前面對不對，誤差一路往下游傳遞、甚至被放大。

具體例子：llava 把「3 隻貓」誤判成「2 隻貓」，這個錯誤數字會原封不動出現在給 qwen3 的文字裡。qwen3 不可能發現這個數字錯了——它只能相信自己收到的文字輸入。這正是⑤「自我檢查機制」站裡定義的 Intrinsic Hallucination 可能發生的場景之一，只是誤差源頭不是 qwen3 自己，是上游的 llava。

2. 跟 End-to-End 架構相比

原生多模態模型理論上比較不容易出現這種特定形式的誤差串接，因為視覺資訊到語言生成在同一模型內部、用連續向量傳遞，沒有「先壓縮成離散文字、再讓下一階段重新解讀」的硬性邊界。但這不代表它完全沒有幻覺問題——只是把風險從「管線階段間的資訊落差」換成「模型內部對視覺特徵的理解偏差」。

3. 如何緩解誤差串接風險

  • 🔁 多次取樣＋比對：讓 llava 對同一張圖回答同一問題好幾次（呼應「進階方向」子地圖②的 Self-Consistency），不一致時標記低信心
  • 🎯 結構化輸出約束：只需要特定資訊時讓 llava 直接回答結構化格式，減少誤讀空間
  • 🔍 關鍵資訊覆核：重要判斷讓 qwen3 拿到描述後主動追問 llava 更具體的問題，形成一個小型 ReAct 迴圈

本專案目前是最簡單的單次轉譯、直接採信版本，這三個方向是可能的強化空間，取捨在於額外工程複雜度換更高可靠度是否划算。
