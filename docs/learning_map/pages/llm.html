🧠 LLM 到底是什麼

在你動手設計任何 harness 邏輯之前，先把這件事刻進直覺：LLM 不是一個有意圖的實體，它是一個函式。這個認知落差沒處理好，之後寫的每一層架構都會帶著錯誤的假設。

LLM（Large Language Model，例如 qwen3_8b）能力邊界很清楚，先把它當成一個黑盒子來看：

  • 它只做一件事：輸入一段 token 序列 → 輸出下一個 token 的機率分佈
  • 它沒有任何執行能力：不能讀檔案、不能發請求、不能跑程式碼——這些全部要靠外層程式代勞
  • 它無狀態（stateless）：每次呼叫都是獨立的一次運算，上一句說過什麼，它自己完全不知道
  • 它沒有「現在」的概念：不知道現在幾點、不知道自己上次被呼叫是什麼時候、不知道眼前這個請求跟上一個是不是同一個使用者
我見過不少人在設計初版架構時，不自覺把 LLM 當成一個「有記憶、會主動做事」的黑盒子去設計系統，結果整套東西繞了一大圈才發現問題出在最根本的假設上。所有看起來「聰明的行為」——讀檔案、呼叫工具、查資料——都不是模型自己做的，是外層程式代為執行、再把結果餵回去讓它繼續往下想。把這點當成設計的第一原則，後面會省很多力氣。

它實際在算什麼

核心運算很單純：給一段文字，算出「下一個 token 最可能是什麼」，然後重複這個過程——算完一個，接到原文後面，再算下一個，一個 token 一個 token 往下生成，直到觸發停止條件。

輸入：「今天天氣」
第1次：「今天天氣」+ 最可能的下一字 → 「今天天氣很」
第2次：「今天天氣很」+ 最可能的下一字 → 「今天天氣很好」
第3次：「今天天氣很好」+ 最可能的下一字 → 「今天天氣很好。」
...直到觸發停止訊號

這解釋了一個你可能已經觀察到的現象：回答有時候會「停不下來」或「突然斷掉」——因為它從來不是「想完整句再一次吐出來」，是逐字生成的。本專案的 think 參數（agent_loop(messages, think, verify)）打開時，模型會先產生一段推理過程再給答案，本質上還是同一套逐字生成機制，只是多讓它先寫一段草稿。

Token 是什麼，為什麼要懂這個

模型處理的最小單位不是「一個中文字」或「一個英文單字」，是 token——文字被切成更小片段後再編號的結果：

原始文字可能的切法（示意）
你好["你", "好"] 或 ["你好"]，依模型的分詞策略而定
Hello["Hello"] 或 ["Hel", "lo"]，英文常被切成字根

每個 token 最後都對應一個數字編號，模型內部從頭到尾只跟數字打交道，文字只是給人看的介面。這件事直接牽動 context window 限制、API 計費、中英文處理成本差異——下一站會把這塊攤開講。

為什麼它「沒有記憶力」這件事比聽起來更重要

每次呼叫都是一次全新的運算，運算結束，所有中間狀態就丟了——它不會自己留存上一輪對話的任何東西。你會在介面上感覺到它「記得」，純粹是因為外層程式每次都把歷史對話重新整段送進去。這不是什麼邊角細節，這是整套系統設計要繞著走的核心限制。

本專案怎麼處理這個限制，在「記憶與 RAG」子地圖有完整拆解——簡單說，就是 harness 自己把最近幾輪對話、加上語意相關的舊對話整理好，每次重新送進去。

它要怎麼「做事」

它不會真的去按按鈕、開檔案。它能做的事只有一種：吐出一段文字。這段文字可能是：

  • 要直接回給使用者看的內容
  • 一段符合特定格式的文字，代表「請求呼叫某個工具」

工具有沒有真的被執行、執行結果是什麼，它完全不知道——這是下一站 Harness 的職責範圍。它只會在下一輪被告知「工具執行結果是這樣」，然後根據這個結果繼續推進。

幾個新手容易卡住的地方

它「看起來」記得我們聊過什麼，這是怎麼回事？

因為每次請求，harness 都把之前的對話整段重傳（下一站細講）。模型本身零儲存能力，記憶的錯覺完全來自外層程式重複餵資料這個動作。

訓練時學到的知識，算不算「記憶」？

那是另一回事，叫參數裡的知識——訓練時看過的海量文字，被壓進模型的數字權重裡，這部分固定不變，不會因為你跟它對話而更新。真正會變動的，只有每次對話時當下塞進去的文字，這才是這張地圖裡「記憶」這個詞指的東西，兩者不要混為一談。

它會不會「亂講」？

它沒有說謊的意圖，它只是在執行「猜下一個 token」這個動作——猜錯了，或者訓練資料裡本來就沒有正確答案，它照樣會很有自信地把猜測講出來，這就是幻覺（hallucination）。這是個常態，不是例外，核心鏈路第五站「自我檢查機制」整節在處理這個問題。

🎓 深入機制（進階，可選讀）

上面的說法足夠支撐這張地圖的其他站點往下走。如果你想知道背後真正的技術機制，這一節把神經網路、Transformer 架構、注意力機制、機率取樣、訓練流程攤開講清楚。

1. 參數：模型到底是什麼

LLM 本質上是一個神經網路——由大量可調整的數字組成的數學函式。這些數字叫參數（parameters）或權重（weights）。「qwen3:8b」裡的 8B 就是 80 億個參數。訓練的過程，就是不斷調整這 80 億個數字，讓這個函式在「給定前文，猜下一個 token」這個任務上越來越準。

把模型想成一個函式：f(前文 token 序列) → 下一個 token 的機率分佈。這個函式的具體形狀由 80 億個參數決定，訓練在調整這些參數，推論（你平常聊天時）只是把這個函式算一次，不會改動任何參數。

2. Transformer 架構：資料怎麼流過模型

現代 LLM（包括 qwen3）幾乎都基於 2017 年提出的 Transformer 架構，精確地說是其中的 Decoder-only 變體。輸入進來後，大致依序流過這幾層：

層作用
① Embedding 層把每個 token 編號轉成高維度向量，語意相近的 token 在向量空間裡位置也相近
② 位置編碼Transformer 本身不知道 token 順序，要額外把位置資訊加進向量
③ 多層 Self-Attention + Feed-Forward堆疊數十層，每層讓每個 token 向量參考整段文字裡其他 token 的資訊，逐層提煉更抽象的語意表示
④ 輸出層把最後一層向量轉成「每個可能下一個 token」的機率分佈

3. Self-Attention：它怎麼「理解上下文」

這是 Transformer 的核心設計，讓模型處理每個 token 時能回頭參考整段輸入裡的其他 token，自動判斷該多看哪些字。

具體做法：每個 token 向量被轉成三個角色——Query（查詢）、Key（鍵）、Value（值），再用公式算出關注權重：

Attention(Q, K, V) = softmax( Q·KT / √dk ) · V
  • Q·KT：算「這個字的查詢」跟「其他每個字的鍵」有多匹配
  • / √dk：數值縮放，避免數字極端化，訓練更穩定
  • softmax(...)：把匹配分數轉成總和為 1 的權重比例
  • · V：按這個比例加權平均其他字的值，得到「參考完上下文」的新表示

舉例：處理「他把球丟給她」裡的「她」，Self-Attention 會學會多關注「球」「丟」、少關注「把」這種虛詞。這套判斷不是人寫規則教的，是訓練時從大量文字裡自己學出來的。

模型通常同時跑多組這種計算，稱 Multi-Head Attention，每組可能學會關注不同種類的語言關係，最後把結果合併。

4. Softmax：從向量到機率分佈

跑完所有 Transformer 層後，最後一個 token 位置的向量經過輸出層，變成一串長度等於詞彙表大小的分數，叫 logits。這些分數本身沒意義，要經過 softmax 轉成總和為 1 的機率分佈：

P(tokeni) = elogiti / Σ elogitj

這才是「猜下一個字」的真正數學意義——模型不是直接決定下一個字，是對詞彙表裡每個可能的 token 都算出機率，再依取樣策略（下一節）選一個。

5. 取樣策略：怎麼從機率分佈選出一個字

  • 🎯 Greedy：永遠選機率最高的，結果固定可重現，但容易顯得呆板、容易卡進重複迴圈
  • 🌡️ Temperature：取樣前把 logits 除以 T。T 越小分佈越尖銳（接近 Greedy）；T 越大分佈越平滑，輸出變化性越高
  • 🔝 Top-k / Top-p：只在機率最高的 k 個候選（Top-k）或累積機率達 p 的候選集合（Top-p）裡取樣，避免選到低機率、容易語無倫次的詞
這解釋了「進階方向」子地圖②多數決驗證為什麼有效：取樣本身帶隨機性，同一問題多問幾次，模型走的機率路徑不同，統計上「多數」答案通常比單次結果穩健。

6. 訓練的三個階段

階段做什麼目標
① 預訓練在海量文字上反覆做「猜下一個字」訓練學會語言文法、世界知識、推理能力的基礎
② 監督微調（SFT）用「問題—理想回答」配對資料微調學會對話、學會遵循指令，而不只是接龍文章
③ 對齊（RLHF / DPO）根據人類對多個回答的偏好排序調整行為讓回答更符合期待的風格、更安全

第一節提過「固定不變的知識」，是階段①壓進參數裡的；②③把模型從「只會接龍」變成「會對話、會用工具」——這也是為什麼同一個基礎模型，不同微調方式會表現出完全不同的能力和風格。

7. Context Window 的技術真相

「能看的 token 數有上限」這件事，原因在 Self-Attention 公式的 Q·KT——每個 token 要跟每個其他 token 都算一次關聯分數，輸入長度 n 個 token，計算量是 n² 量級。長度加倍，運算量變四倍，這是硬體限制，不是「記不住」。

這也解釋了「記憶與 RAG」子地圖裡，harness 為什麼要費心篩選送進去的內容，而不是把全部歷史對話都塞進去——不只是浪費，是計算量會隨長度平方爆炸，長度越長，等待時間也越久。
