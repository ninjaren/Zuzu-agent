# ZuZu 操作指南

## 啟動

雙擊專案根目錄的 `start.bat`，它會依序：

1. 啟動 Ollama 服務
2. 確認模型已下載（已有則跳過）
3. 開啟瀏覽器到 `http://127.0.0.1:5000`
4. 啟動 Flask app

> 第一次問問題時需要等幾秒讓模型載入，之後就很快。

---

## 模型常駐時間（KEEP_ALIVE）

控制 qwen3:8b 在記憶體裡待多久，設定在 `start.bat` 第五行：

```bat
set OLLAMA_KEEP_ALIVE=600
```

| 值 | 效果 | 適合情境 |
|---|---|---|
| `0` | 用完立刻卸載（約 10GB 釋放）| 只偶爾用、很在乎記憶體 |
| `600` | 閒置 10 分鐘後自動卸載 | **建議值**，平衡方便與資源 |
| `3600` | 閒置 1 小時後卸載 | 一整天頻繁使用 |
| `-1` | 永遠不卸載（直到手動關閉） | 長時間作業 |

改完後**重新執行 start.bat** 才會生效。

## 常用指令

### 確認模型狀態

```bash
ollama ps
```

顯示目前載入中的模型、記憶體用量、幾分鐘後卸載。

### 查看已下載的模型

```bash
ollama list
```

### 手動預熱模型（KEEP_ALIVE=0 的情況下使用前先跑）

```bash
ollama run qwen3:8b "hi"
```

等它回應後，馬上去 ZuZu 使用，這樣第一次就不會 timeout。

### 手動卸載模型（立刻釋放記憶體）

```bash
ollama stop qwen3:8b
```

## 疑難排解

### ⚠ HTTPConnectionPool: Read timed out

**原因**：Ollama 正在從硬碟載入模型（5.2GB），超過 120 秒。

**解法**：
- 把 `KEEP_ALIVE` 改成 `600` 以上，讓模型常駐記憶體
- 或先執行 `ollama run qwen3:8b "hi"` 預熱，再使用 ZuZu

### ⚠ bind: Only one usage of each socket address

**原因**：Ollama 已經在跑了，不需要再開一個。這是正常現象，可以忽略。

### ZuZu 頁面打不開（瀏覽器空白）

**原因**：Flask app 還沒啟動完成。等 `start.bat` 視窗出現 `Running on http://127.0.0.1:5000` 再重整頁面。

---

## 關閉

直接關掉 `start.bat` 的視窗即可停止 Flask。

Ollama 服務會繼續在背景跑（這是正常的）。若要完全關閉 Ollama，在工作列右下角找到 Ollama 圖示 → 右鍵 → Quit。
